# Fileward → SIEM → SOAR

В этом каталоге находятся шаблоны конфигурации и адаптер входных данных.
Они не устанавливают агенты, не изменяют действующий сервер Wazuh и не создают
сценарий на удалённом экземпляре Shuffle. Локальные проверки подтверждают
синтаксис XML и преобразование данных. Реальную доставку нужно проверить
на собственном стенде с выбранными версиями компонентов.

## Wazuh

1. Запустите Fileward с абсолютным путём `--journal` вне наблюдаемого дерева.
   Предоставьте коллектору Wazuh необходимые права чтения журнала и прохода
   по родительским каталогам. Новый журнал по умолчанию имеет права 0600.
2. Добавьте содержимое `wazuh/agent-localfile.xml` в `ossec.conf` конечного узла,
   заменив USER и путь. JSON-декодер Wazuh разбирает каждую строку; отдельный
   пользовательский декодер текстовых логов не требуется.
3. Добавьте правила из `wazuh/local_rules.xml` к локальным правилам сервера.
   Сначала убедитесь, что ID 100800..100804 не заняты. Проверьте настоящую строку
   Fileward через `wazuh-logtest`.
4. Перезапустите или перезагрузите компоненты согласно установленной версии Wazuh.
   Убедитесь, что отказ действия вызывает правило 100801, а потеря событий
   очереди — правило 100802. Успешные операции остаются событиями базового уровня,
   без формирования оповещения. Интеграция отправляет в Shuffle оповещения,
   а не все исходные записи журнала.
5. Коллектор должен корректно отслеживать переименованные файлы. Fileward ротирует
   журнал в `.1`/`.2`/`.3`; настройте скорость сбора и срок хранения так, чтобы
   непрочитанные сегменты не удалялись. Не подключайте эти же сегменты дополнительно
   через маску, если не предусмотрена намеренная обработка повторов.

Официальная документация:

- [Сбор журналов через localfile](https://documentation.wazuh.com/current/user-manual/reference/ossec-conf/localfile.html).
- [JSON-декодер](https://documentation.wazuh.com/current/user-manual/ruleset/decoders/json-decoder.html).
- [Синтаксис правил](https://documentation.wazuh.com/current/user-manual/ruleset/ruleset-xml-syntax/rules.html).

## Shuffle

1. Создайте и запустите триггер Webhook. Используйте URL, созданный вашим
   развёртыванием, вместо предположения об адресе облачной или локальной установки.
   Настройте подходящий способ аутентификации триггера.
2. Добавьте содержимое `wazuh/shuffle-integration.xml` в конфигурацию сервера
   с полученным URL. Шаблон фильтрует группу `fileward` и уровень >= 3.
   Запись аудита Fileward находится в поле `data` оповещения.
3. Используйте логику `shuffle/normalize.py` как первый шаг проверки и
   преобразования данных. Адаптер принимает непосредственную запись Fileward
   либо оповещение Wazuh с вложенными данными. Локальный запуск:
   `python3 integrations/shuffle/normalize.py < saved-wazuh-alert.json`.
4. Используйте полученный `dedup_key` в постоянном хранилище или при обращении
   к идемпотентной системе назначения. Повторная доставка одного оповещения
   не должна создавать дубли заявок. Параллельные операции «проверить, затем
   вставить» сами по себе не обеспечивают доставку строго один раз. Используйте
   атомарную операцию хранилища или идемпотентность системы назначения, если доступны.
5. Разделяйте обработку отказов по коду: таймаут, права, конфликт, потеря наблюдения.
   Дополняйте метаданные и создавайте учебное уведомление или заявку. Значения
   пути и сообщения нельзя интерпретировать как команды shell. Адаптер не
   загружает содержимое файлов и не выполняет действия на конечном узле.

До признания интеграции стенда завершённой проверьте отклонение неподдерживаемой
схемы, повтор одного оповещения дважды, отсутствие обязательных полей и получение
настоящего оповещения по всей цепочке.

Официальная документация:

- [Интеграция Wazuh с внешними API и Shuffle](https://documentation.wazuh.com/current/user-manual/manager/integration-with-external-apis.html).

## Другие SIEM

Версионируемый JSONL-файл не привязан к Wazuh. Читайте его коллектором и
сопоставляйте поля: `provider` → `event.provider`, `timestamp` → `@timestamp`,
`kind` → `event.action`, `outcome` → подходящее поле выбранной платформы,
`watch_root`/`relative_path` → `file.path`. Не все результаты Fileward являются
допустимыми значениями результата в ECS: `success`/`failure` сопоставляются напрямую,
а `skipped`/`ready`/`matched` требуют отдельной классификации. Используйте
`event_id` для устранения повторов доставки, `parent_id` — для связывания цепочек правил.
